{{if eq .Role "reviewer"}}Every finding at `medium` or above, plus `low` ones marked `trivial: yes`, is sent back to be fixed before a pull request opens; anything else goes into the pull request for a person to weigh. A conductor deciding the task may set its own bar. Mark `trivial: yes` only when the smallest fix is obvious, local and a few lines. A finding at `medium` or above states its `acceptance`; its `caused_by_fix` is `yes` when the problem is in code the last fix wrote.{{else}}Severity decides what happens next: `blocking`, `high`, `medium` send the change back to be fixed before a pull request opens; anything else goes into the pull request for a person to weigh. So a finding that means an acceptance criterion is not met must be one of `blocking`, `high`, `medium`, however small the fix. A finding at a severity that sends the change back states its `acceptance`.{{end}}

Drive a real browser with Playwright (Python: `python3 -m playwright`, the `playwright` package; Chromium is installed), at a 1920×1080 viewport unless a criterion is about another size. Record each journey as a video — create the browser context with `record_video_dir` and a `record_video_size` equal to the viewport (if unset, Playwright scales the video down) — at a pace a person can follow: launch with `slow_mo` of about 250 ms and pause about one second on each state that matters. Keep a failure in the recording; do not cut it out.

If the project has its own walkthrough recorder, use it. Otherwise draw what the video cannot show by itself: Playwright records no mouse pointer, so add a pointer that follows the mouse, a ring on each click and a caption bar with `context.add_init_script`, styled through `element.style` so a strict page's CSP does not block them (do not turn the page's CSP off: that hides the errors you report). Glide the mouse to each control (`page.mouse.move` with `steps`) before you click it; type short inputs at a readable pace and fill long text. Do in the UI every step a criterion is about; API calls and typed URLs are for setup, captioned as setup, unless the criterion is about them. Caption each step with what is on screen.

If text-to-speech tools are already installed (`edge-tts`, `espeak-ng` or `piper` on PATH, and an `ffmpeg` other than Playwright's, which only records and cannot edit), narrate the captions into the video; if narration fails once, keep the video captioned but silent and say so in `acceptance.md`. With such an `ffmpeg`, also shorten waits longer than about ten seconds in the video a person watches, mark each sped-up part, and keep the uncut recording as one of the files you publish; without one, leave the waits in and caption what they wait for.

When you are done, close the context so the video is written, then publish the video, each screenshot and `acceptance.md` with `dude publish FILE --name NAME --description "…"` (for example `dude publish /tmp/videos/abc.webm --name walkthrough.webm --description "The sign-in flow, end to end"`, `--name 01-signed-in.png`), named so the order reads; a description is one short line saying what the file shows.

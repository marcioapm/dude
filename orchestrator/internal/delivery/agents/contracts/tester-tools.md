Drive a real browser with Playwright (Python: `python3 -m playwright`, the `playwright` package; Chromium is installed), at a 1920×1080 viewport unless a criterion is about another size. Record each journey as a video — create the browser context with `record_video_dir` and a `record_video_size` equal to the viewport (if unset, Playwright scales the video down) — at a pace a person can follow: launch with `slow_mo` of about 250 ms and pause about one second on each state that matters. Keep a failure in the recording; do not cut it out.

If the project has its own walkthrough recorder, use it. Otherwise, as Playwright records no mouse pointer, use `context.add_init_script` to add a pointer that follows the mouse, a ring on each click and a caption bar. Style them through `element.style` and animate them with `element.animate`, never a `<style>` element, so a strict page's CSP does not block them; do not turn the page's CSP off: that hides the errors you report. Give them `pointer-events: none` so they never take a click. Glide the mouse to each control (`page.mouse.move` with `steps`) before you click it; type short inputs at a readable pace and fill long text. Caption each step with what is on screen. Do in the UI every step a criterion is about; API calls and typed URLs are setup and captioned as setup, unless a criterion is about them: then caption the URL or request itself.

If text-to-speech tools are already installed (`edge-tts`, `espeak-ng` or `piper` on PATH, and an `ffmpeg` other than Playwright's, which can only record), narrate the captions into the video; if narration fails once, stop narrating for this Run: keep the videos captioned but silent and say so in `acceptance.md`. With such an `ffmpeg` on PATH, also speed up waits longer than about ten seconds, mark each sped-up part, and keep the uncut recording as one of the files you publish; without one, or if the edit fails, leave the waits in and caption what they wait for.

When you are done, close the context so the video is written, then publish the video, each screenshot and `acceptance.md` with `dude publish FILE --name NAME --description "…"` (for example `dude publish /tmp/videos/abc.webm --name walkthrough.webm --description "The sign-in flow, end to end"`, `--name 01-signed-in.png`), named so the order reads; a description is one short line saying what the file shows. Publish each video with `--poster` naming the screenshot that best shows its outcome, usually the last criterion's, e.g. `dude publish /tmp/videos/abc.webm --name walkthrough.webm --poster 04-saved.png --description "…"`.
